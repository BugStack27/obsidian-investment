# 统一加减仓弹窗 — 决策记录

> 状态：✅ 已验收（2026-10-27）

## 1. 目标与范围

用一个弹窗承担基金/股票的全部交易录入：命令「加减仓」、基金/股票记录块的加仓/减仓/分红按钮与表格行编辑、买卖信号确认、近期操作「记一笔买卖」都收敛到 `PositionTradeModal`。

基金按「只填能确定的那个数」录入：**买入只填金额**（份额按记录日净值推导），**卖出只填份额**（金额按记录日净值推导），**分红只填金额**。股票录数量与价格。

不做：不扩展多记录块定位；不做历史错单的批量追溯改写。

## 2. 关键决策

| 决策点 | 结论 | 理由 |
|------|------|------|
| 入口收敛 | 所有新增/编辑入口共用一个弹窗；笔记按钮、行编辑、信号确认场景锁定目标 | 防止写错笔记 |
| 标的选择 | 全库基金/股票笔记分组 + 本地关键词过滤，纯本地扫描 | 零网络、避免请求 |
| 分红 | 仅基金出现的第三种类型 | 股票无现金分红记录口径 |
| 基金买入 | 只填金额，份额留空由数据层按记录日净值推导；当日成交用估值/最新净值预估份额 | 申购确认前拿不到最终份额 |
| 基金卖出 | 只填份额，金额由数据层推导；展示可卖份额并拦截超限 | 消除「只填金额、份额超限」旁路（细则见 `sell-quantity-guard.md`） |
| 缺项无法补全 | 买入/卖出缺失的金额或份额无法由净值补齐时标记「待确认」，不计入持仓与收益 | 宁可不出数，也不以 0 成本入账 |
| 编辑已有记录 | 已记录的份额不因金额变化而重算，原样保留 | 份额可能来自平台确认，重算会改写历史 |
| 预估口径 | 弹窗预估只在当日成交时使用；历史日期只提示「按记录日净值补全」 | 估值是预估，确认净值才入账 |
| 保存校验 | 买入/分红要求金额 > 0，卖出要求份额 > 0，股票要求数量与价格均 > 0 | 与各自的唯一输入口径对齐 |
| 日期 | 原生 date 控件，不限未来日期 | 可预录挂单成交 |

## 4. 关键修正与教训

- **买入只填份额曾被记成金额 0**（成本 0、收益与年化虚高、持仓成本线失效导致不再出信号）→ 买入缺金额与卖出缺金额一样按净值补；缺项无法补时统一标记待确认。
- **隐藏份额输入后，编辑旧记录不能按金额重算份额** → 原份额保留并在提示中说明「保存时保持不变」。
- **卖出隐藏金额字段是数据层推导的前提** → 校验口径只剩份额，避免留下只填金额的旁路。
- **股票不套用基金的「只填一个数」** → 股票金额由数量 × 价格得出，数量不可省略。

## 5. 已知边界

- 每个笔记只写首个记录块（与全链路 `transformRecordBlock` 语义一致）。
- 标的选择器在打开时一次性扫描，之后新建的笔记需重开弹窗。
- 股票名称在笔记按钮场景取行情名，命令/选择器场景取笔记标题。
- 切换类型会清空对立字段（金额/份额）。
- 「待确认」记录被排除在持仓与收益之外，清仓判断与可卖份额会偏高或不完整。
- 多记录块、历史错单均不做自动修正。

## 6. 后续候选

- 对「待确认」记录给出记录块之外的显式提醒。
- 标的选择器改为增量刷新，避免一次性扫描。
