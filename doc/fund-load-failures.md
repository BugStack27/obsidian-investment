# 加载失败的基金不再静默缺席汇总 — 决策记录

> 状态：✅ 已验收（2026-10-26）

## 1. 目标与范围

加载链路原来把「无记录块」「记录块为空」「加载失败」三种情况统一返回 `null`，失败基金的本金与收益一并从汇总中消失且毫无提示。改为区分「本来就没记录」与「有记录但加载失败」，失败清单随快照下发，在汇总卡、状态栏、近期操作弹窗（含今日档）点名，并支持打开笔记与重新加载。不改动 `fundCount` 语义、今日盈亏与信号计算链路。

## 2. 关键决策

| 决策点 | 结论 | 理由 |
|------|------|------|
| 失败判定 | 仅「有有效记录但净值/读取/汇总失败」算失败；无记录块或仅注释（`entries.length === 0`）视为无记录、不点名 | 刚新建的基金笔记被点名属噪音 |
| 原因粒度 | 四类归一化短原因（净值获取失败 / 无净值数据 / 笔记读取失败 / 持仓汇总失败），原始报错只进 `title` | 原始报错长度不可控，会撑开汇总卡与状态栏 |
| 汇总卡与状态栏 | 一行「N 只基金未纳入统计」+ 悬浮名单，不展开 | 避免长名单撑开底行与状态栏 |
| 操作弹窗 | 买卖汇总行下方常驻提示条，逐条列出名称 + 代码 + 原因，并注明其记录未纳入本列表 | 仅列表为空时提示会漏掉「有记录但缺这本账」的矛盾场景 |
| 交互 | 点击计数行或基金行打开笔记；「重新加载」= 一次 `store.refresh()` | 净值失败不写缓存，重试即恢复 |
| 全失败空态 | 卡片数为 0 时直接列失败清单；`s.error` 仍优先显示 | 「还没有任何基金持仓」与事实不符 |
| 计数口径 | `fundCount` 仍只统计成功基金 | 「共 N 只」语义不变，缺口由失败行承担 |
| 清单刷新 | 仅全量刷新重算；盘中估值刷新与信号更新沿用上一轮 | 轻量路径不额外拉净值 |
| 兼容 | `loadFundAnalysis` 保持原签名，改为结果类型的薄封装 | `listHeldFunds`、可卖份额逻辑零改动 |

## 4. 关键修正与教训

- **三种 `null` 合一** → 调用方无法区分，失败基金静默消失；改为「ok / no-record / failed」结果联合类型，旧入口保留薄封装。
- **操作弹窗空态与「已记录」Notice 自相矛盾** → 有失败基金时空态文案必须改为「已纳入统计」口径。
- **Obsidian `Menu` 无 tooltip API** → 原始报错只能放在计数行与提示条行的 `title` 上。
- **失败清单若跟随估值刷新重算** → 盘中会额外拉净值；改为只在全量刷新重算。
- **名称回退需分两套** → 失败清单回退 `file.basename`（便于识别），ok 路径沿用原有 `code` 回退，不改既有展示。

## 5. 已知边界

- 无记录块或记录块仅注释的基金永不被点名，也不进入清单。
- 失败基金仍按原逻辑参与实时估值批量请求，无额外副作用。
- 今日盈亏与信号计算链路口径不变；失败期间该基金无卡片、无图表。
- 本次未做 Obsidian 内实机 UI 验证，提示条样式与悬浮交互需人工核对。
