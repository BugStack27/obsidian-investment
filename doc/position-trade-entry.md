# 统一加减仓弹窗与录入防护 — 决策记录

> 状态：✅ 已验收（2026-10-27）

## 1. 目标与范围

用一个弹窗承担基金 / 股票的全部交易录入：命令「加减仓」、记录块加仓 / 减仓 / 分红按钮与表格行编辑、买卖信号确认、近期操作「记一笔买卖」都收敛到 `PositionTradeModal`。基金按「只填能确定的那个数」录入：买入只填金额（份额按记录日净值推导）、卖出只填份额（金额推导）、分红只填金额；股票录数量与价格。保存前校验卖出份额不超过当前可卖份额，日期统一用原生控件与共享归一化口径。不扩展多记录块定位，不追溯改写历史错单。

## 2. 关键决策

| 决策点 | 结论 | 理由 |
|------|------|------|
| 入口收敛 | 所有新增 / 编辑入口共用一个弹窗；笔记按钮、行编辑、信号确认场景锁定目标 | 防止写错笔记 |
| 标的选择 | 全库基金 / 股票笔记分组 + 本地关键词过滤，纯本地扫描 | 零网络请求 |
| 分红 | 仅基金出现的第三种类型 | 股票无现金分红记录口径 |
| 基金买入 | 只填金额，份额留空由数据层按记录日净值推导；当日成交用估值 / 最新净值预估份额 | 申购确认前拿不到最终份额 |
| 基金卖出 | 只填份额，金额由数据层推导；隐藏金额输入框 | 份额成为唯一录入值，消除「只填金额」旁路 |
| 股票录入 | 数量 + 价格，金额由数量 × 价格得出 | 不套用基金「只填一个数」，数量不可省略 |
| 缺项无法补全 | 买入 / 卖出缺失金额或份额且无法按净值补齐时标记「待确认」，不计入持仓与收益 | 宁可不出数，也不以 0 成本入账 |
| 编辑已有记录 | 原份额不因金额变化而重算，原样保留 | 份额可能来自平台确认，重算会改写历史 |
| 预估口径 | 弹窗预估只在当日成交时使用；历史日期只提示「按记录日净值补全」 | 估值是预估，确认净值才入账 |
| 保存校验 | 买入 / 分红要求金额 > 0；卖出要求份额 > 0；股票要求数量与价格均 > 0 | 与各自唯一输入口径对齐 |
| 可卖份额范围 | 全部卖出入口：基金 / 股票记录块减仓与编辑、「加减仓」命令、近期操作「记一笔买卖」、信号「确认卖出」 | 任一入口漏校验即可写出错单 |
| 编辑卖出可用份额 | 当前持仓 + 该记录原份额 | 先归还自己占用的份额，避免只改小数位被误拦 |
| 无法判定持仓 | `null` 时不拦截，提示「无法获取当前可卖份额，本次不校验上限」 | 不误阻挡正常卖出 |
| 解析进行中 | `loading` 时拦下并提示「正在读取当前可卖份额，请稍候」 | 避免加载窗口内抢跑写入 |
| 浮点比较 | `shares > available + 1e-6` 才拦截 | 规避小数误差 |
| 存量超额记录 | 不追溯、不告警，`holdShares < 0 → 0` 钳制保留 | 只保证新录入不再超额 |
| 日期控件 | 原生 `input[type=date]`，不限制未来日期 | 值恒为合法 ISO 或空串；可预录已挂单成交 |
| 日期合法判定 | 抽共享工具函数 `isValidRecordDate` / `normalizeRecordDate`，解析、导入、弹窗三处共用 | 避免口径分叉；月 / 日允许 1–2 位，拒绝日历上不存在的日期 |
| 存量坏日期 | 只读归一化并补零，不回写笔记 | 「打开即写盘」会污染同步与版本控制 |

## 4. 关键修正与教训

- **买入只填份额曾被记成金额 0** → 成本 0、收益与年化虚高、持仓成本线失效导致不再出信号；买入缺金额与卖出缺金额一样按净值补。
- **隐藏份额输入后，编辑旧记录不能按金额重算份额** → 原份额保留并在提示中说明「保存时保持不变」。
- **空记录块返回 0 会拦掉所有卖出** → 与「无法判定不拦截」冲突，改为返回 `null`。
- **可卖份额四舍五入后照抄会被反拦** → 展示按向下取整（基金 4 位 / 股票 2 位）。
- **弹窗内改选标的会残留上一只的读数** → `availableSeq` 自增 + 目标身份校验，丢弃过期结果。
- **买入不应触发额外净值请求** → 非卖出时保持 `idle`，不提示也不解析。
- **编辑旧记录时日期控件显示空白** → 控件只接受合法 ISO 或空串，`init.date` 必须先归一化（失败退回今天）。
- **先设值再改 `type` 会被浏览器 sanitize 清空** → 必须先赋 `type = 'date'` 再 `setValue`。
- **`new Date` 会把 0–99 年份映射到 19xx** → 归一化须显式限制年份范围并用回读比对拦下非法日期。

## 5. 已知边界

- 每个笔记只写首个记录块（与全链路 `transformRecordBlock` 语义一致）。
- 标的选择器打开时一次性扫描，之后新建的笔记需重开弹窗。
- 切换类型会清空对立字段（金额 / 份额）。
- 「待确认」记录被排除在持仓与收益之外，清仓判断与可卖份额会偏高或不完整。
- 历史卖出记录一旦编辑，金额将按「份额 × 当日净值」重算并留空存储，原手填金额不保留。
- 早期「只填金额」的卖出记录份额为 0，编辑时必须补填份额，否则无法保存。
- 净值缺失导致卖出处于 `pending` 时不计入持仓，可卖份额会偏高。
- 多记录块、历史错单均不做自动修正。

## 6. 后续候选

- 对「待确认」记录给出记录块之外的显式提醒。
- 标的选择器改为增量刷新，避免一次性扫描。
- 存量超额卖出记录的巡检与告警。
