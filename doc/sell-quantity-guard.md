# 减仓数量超持仓拦截 — 决策记录

> 状态：✅ 已验收（2026-10-25）

## 1. 目标与范围

统一加减仓弹窗原先只校验「填了东西」，不校验「卖得比持有多」，也没有可卖参照：多打一位小数或忘记已卖过一轮，就会写入超额卖出记录。基金侧 `summarizeHolding` 把负持仓钳成 0，但累计投入继续按卖出金额扣减，出现「份额 0 却显示正收益」；股票侧同理。本次覆盖全部卖出入口，保存前校验卖出份额 ≤ 当前可卖份额，并消除基金卖出「只填金额」的旁路。不追溯处理已写入的超额记录，不改记录格式。

## 2. 关键决策

| 决策点 | 结论 | 理由 |
|------|------|------|
| 拦截范围 | 全部卖出入口：基金记录块减仓/编辑、股票记录块减仓/编辑、`加减仓` 命令、近期操作 `记一笔买卖`、信号 `确认卖出` | 任一入口漏校验即可写出错单 |
| 基金卖出金额 | 隐藏金额输入框，金额由 `resolvePending` 按「份额 × 当日净值」推导 | 份额成为唯一录入值，校验口径唯一；置灰仍会被误填 |
| 编辑已有卖出记录 | 可用份额 = 当前持仓 + 该记录原份额 | 先归还自己占用的份额，避免只改小数位被误拦 |
| 可卖份额呈现 | 在份额/数量输入项下用 `setDesc` 显示「当前可卖 X」，超限保存时 Notice 提示上限 | 录入前有参照，录入后有兜底 |
| 无法判定时 | `null` 时不拦截，提示「无法获取当前可卖份额，本次不校验上限」 | 不误阻挡正常卖出 |
| 解析进行中 | `loading` 时拦下并提示「正在读取当前可卖份额，请稍候」 | 避免加载窗口内抢跑写入 |
| 浮点比较 | `shares > available + 1e-6` 才拦截 | 规避小数误差 |
| 存量数据 | 不追溯、不告警，`holdShares < 0 → 0` 钳制保留 | 只保证新录入不再超额，钳制继续兜历史错单 |

## 4. 关键修正与教训

- **空记录块返回 0 会拦掉所有卖出** → 与「无法判定不拦截」冲突，改为返回 `null`，与命令侧语义对齐。
- **可卖份额四舍五入后照抄会被反拦** → 展示按向下取整（基金 4 位 / 股票 2 位）。
- **弹窗内改选标的会残留上一只的读数** → `availableSeq` 自增 + 目标身份校验，丢弃过期结果。
- **买入不应触发额外净值请求** → 非卖出时 `availableState` 保持 `idle`，不提示也不解析。

## 5. 已知边界

- 历史卖出记录一旦编辑，金额将按「份额 × 当日净值」重算并留空存储，原手填金额不保留。
- 早期「只填金额」写下的卖出记录份额为 0，编辑时必须补填份额，否则无法保存。
- 净值缺失导致卖出处于 pending 时不计入持仓，可卖份额会偏高（既有语义未改）。
- 股票卖出仍保留数量与价格字段，仅新增可卖提示。
