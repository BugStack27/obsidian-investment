# 股票记录块行操作与总收益 — 决策记录

> 状态：✅ 已验收（2026-11-01）

## 1. 目标与范围

为股票笔记 `stock-record` 表格补齐与基金侧一致的行操作：每行提供编辑 / 删除图标，编辑复用统一弹窗 `PositionTradeModal`（锁定标的与类型），删除复用 `ConfirmModal` 先确认。同时在汇总中补一套「总口径」，多渲染一张「总收益」卡，让部分卖出后仍能看到整段持仓的收益与收益率。不改动表格列结构、写入链路与 K 线标记，不提供批量操作。

## 2. 关键决策

| 决策点 | 结论 | 理由 |
|------|------|------|
| 编辑弹窗 | 复用 `PositionTradeModal`，锁定标的与买卖方向 | 与基金编辑入口一致；记错方向需删掉重录 |
| 分红行 | 只显示删除按钮，不可编辑 | 分红行无数量与价格，算不出回显价格 |
| 价格回显 | `价格 = 金额 ÷ 数量`，固定 2 位小数；传 `price` 而非 `amount` | 行内只存金额与数量，价格是派生量；A 股报价即 2 位 |
| 操作列样式 | 表头补空字符串，单元格用既有 `inv-ops` 类 | `styles.css` 已全局定义，零 CSS 改动 |
| 写回定位 | 排序时保留原始块内 `lineIdx` | 写回按块内行号定位，不能用排序后下标 |
| 两套口径并存 | `持仓盈亏` = 剩余市值 − 成本基准；`总收益` = 市值 − 净投入 + 分红 | 持仓口径回答「现在浮盈多少」，总口径回答「这段持仓一共赚了多少」 |
| 净投入 | 买入金额累计 − 卖出回款累计 | 卖出回笼的钱已不是投入，留在分母里会把收益算低 |
| 总收益率分母 | 累计买入金额，非净投入 | 与基金 `summarizeHolding` 一致；净投入做分母会在减仓后虚高、清仓时归零 |
| 分红 | 股票记录块也累计分红进总收益 | 表格本就有分红类型，真实收益不能漏 |
| 总收益卡渲染条件 | 有卖出回款或有分红时才渲染 | 从未卖出过的标的，总收益与持仓盈亏完全相同，多一张卡只是噪声 |
| 行情失败 | 未清仓显示 `—`；已清仓仍出数 | 未清仓按 0 市值会得出巨额假亏损；已清仓市值恒为 0，全是已兑现收益 |

## 4. 关键修正与教训

- **股票目标下弹窗只渲染「数量 + 价格」** → 必须传 `price` 而非 `amount`，否则价格回显为 0 并被行情价异步预填覆盖（`priceTouched` 仅在 `price > 0` 时成立）。
- **写回时行号越界** → `replaceRecordAtLine` / `removeRecordAtLine` 返回 null 时抛错，不静默原样写回。
- **`onMutate` 原先不返回 Promise** → 改为返回 `Promise<void>`；加仓 / 减仓、编辑、删除三个调用点都必须处理 rejection。
- **总收益不能写成「持仓盈亏 + 已实现收益」两段相加** → 直接从「市值 − 净投入 + 分红」推导，一个算式即可，卖出回款自然进账。
- **收益率分母不能沿用成本基准** → 减仓后成本基准随剩余持仓缩小，会算出与总收益不匹配的夸张收益率。

## 5. 已知边界

- `type=buy` 但 `shares=0` 的畸形行仍显示编辑按钮（保留补填修复路径），但回显价格为 0 会被行情价覆盖。
- 金额与价格字段不匹配是结构性取舍：手填时把手续费并入金额，保存后金额会有分位级偏差。
- 卖出记录若金额为 0（只录了数量），无法推导回款，总收益会被算低；股票侧没有净值推导来源，不臆造。
- `transformRecordBlock` 只定位笔记内首个 `stock-record` 块，多块笔记会写错块（基金侧同样存在）。
- 弹窗停留期间文件被外部改动时，越界行号可拦、指向他行不可识别。
- `stockRecordBlock.ts` 已超出单文件 200–300 行的软建议，未拆分。

## 6. 后续候选

- 给记录行增加价格列（CSV 第 7 列），让编辑后金额绝对无损。
- 总收益卡副标题增加「已兑现」分项（卖出回款 − 对应成本），需要 FIFO / 均价分摊口径。
- 文件继续增长时抽出 `stockRecordTable.ts`。
